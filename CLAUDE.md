## Commands

Requires `uv` installed at the system level (`curl -LsSf https://astral.sh/uv/install.sh | sh`).

```bash
# Install dependencies
uv sync

# Regenerate the synthetic dataset (outputs to data/raw/)
python generate_dataset.py

# Run a service entry point
python services/01-attribution/main.py

# Run tests for a specific service
python -m pytest services/01-attribution/tests/ -v

# Run a single test
python -m pytest services/01-attribution/tests/test_models.py::test_last_touch -v
```

## Architecture

This is a multi-service analytics monorepo for B2B SaaS marketing intelligence. Each service under `services/` is an independent MVP (attribution, cohort, lead-scoring, funnel-diagnostics, content-attribution) that reads from a shared dataset.

### Data Layer

`data/raw/b2b_attribution.db` is the SQLite source of truth shared across all services. CSV files in `data/raw/` are the same data in flat format. The DB has indices pre-built on all foreign keys and high-cardinality filter columns — prefer SQLite over CSV for multi-table analyses.

The dataset was generated by `generate_dataset.py` using a process-based SCM (Structural Causal Model) that simulates the full B2B funnel: `ga4_session → lead → MQL → opportunity → close`. All funnel probabilities are conditioned on `channel × industry × size_class`.

**Critical field**: `touchpoints.true_marginal_contribution` is the causal ground truth — the marginal contribution each touchpoint actually had in the generative model. Use this to benchmark any attribution heuristic (last-touch, time-decay, etc.) against the real answer.

### Shared Modules (`shared/`)

Code common to all services lives in `shared/`:
- `db.py` — SQLite connection helpers
- `config.py` — paths, constants, global parameters
- `viz.py` — standardized Plotly/Matplotlib theme
- `utils.py` — common utility functions

Services import from `shared` directly; do not duplicate this logic per service.

### Service Structure

Each `services/NN-name/` follows the same layout:
- `main.py` — entry point
- `models/` or `analysis/` — core computation
- `dashboard/app.py` — Streamlit or Dash UI
- `tests/` — pytest tests
- `CLAUDE.md` — service-specific context

### Dataset Intentional Quirks

These are deliberate and should not be "fixed":
- `campaign` column in `leads` and `touchpoints` has name inconsistencies (e.g., `linkedin_prospecao` vs `linkedin_prospeccao`, hyphens vs underscores) — this is realistic dirty data for demonstrating cleaning.
- ~5% of `accounts.industry` and ~4% of `accounts.size_class` are null.
- ~15% of `ga4_sessions.lead_id` is null (anonymous traffic).
- ~3% of `opportunities` have all `stage_*_dt` columns null (simulated CRM data gaps).

### Key Relationships

```
accounts ──< leads ──< opportunities ──< touchpoints
ga4_sessions >── leads (first_touch_session_id)
channel_spend — (join on channel + week)
content_assets >── touchpoints (content_asset_id)
```

Win rate and deal size are functions of `channel × industry × size_class` — aggregations that ignore subpopulation heterogeneity will produce misleading ROAS figures.
